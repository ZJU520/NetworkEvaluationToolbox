## v1.6：修复 NAT "容量满分但类型测不出 → 只给 58 分"（评分缺陷）
- 用户报告的现象：容量 2000/2000 = 100%，NAT 维度却只 58 分。根因：NAT 分 = 类型×0.6 + 容量×0.4；只探到 1 台可用 STUN（bilibili 通、google 当次不通）无法做双服务器映射比对 → 归到 `STUN 部分不可用` 兜底 30 分 → 0.6×30+0.4×100=58。
- 三处修复：
  1) 类型探测改为收集最多 3 台不同 IP 的可响应 STUN，同一 socket 依次尝试比对（原逻辑只试第 2 台，失败即放弃）；新增 `BindingWithRetry`（3 次 × 1.5s）抗瞬时丢包。
  2) 评分语义化：`NatTypeProbe(Text, Determined, AllStunDown)`。类型未分类但容量测得时，不再塞惩罚性占位分，改为 `score = capScore - 5` 并写入"以容量为主"的说明；仅"全部 STUN 不可达"才保留 30 分兜底。
  3) 修复误导建议：原文案只要 natType 含"不可用"就提示"STUN 均无响应/UDP 可能被封"（"部分不可用"也被命中）。现改为仅在 AllStunDown 时给该建议，未分类时给"补 STUN 后重测/在线站点交叉验证"建议。
- 默认 STUN 列表更新（实测 9 台可用：bilibili/google/cloudflare/nextcloud/sipnet/antisip/epygi/hot-chilli/twilio；已失效：miwifi/qq/sipgate/voipbuster）：改为 bilibili + google + cloudflare + twilio + nextcloud + hot-chilli。
- 顺带清掉 SpeedTester 未使用变量 phaseDl 的 CS0219 警告，现 0 警告 0 错误。
- 验证：类型成功判定 Full Cone（两台服务器映射到同一公网端口），NAT 97 分；报告不再出现错误建议。
- 分发包：`NetToolbox_v1.6_绿色版.zip`（66.8MB），已删除 v1.5。

## v1.8：全部测试源改国内优先（用户要求"尽量用国内服务器，防止不成功"）
- 实测结论（本机 2026-11-08）：国内可用 STUN 仅 stun.chat.bilibili.com（douyucdn/hitv/cdnbye/miwifi/qq 全超时）；国内测速源比 Cloudflare 快 5 倍以上。
- 关键设计：`AddrResolver.ResolveIpsAsync` 返回全部 A 记录；NatTester 把「同一域名的多个 IP」当作不同目标（NAT 映射按目标 IP:port 分配），实测 bilibili 解析出 7 个 IP，仅靠国内域名即可完成锥形/对称型判定，不再依赖境外 STUN。
- 测速改造：下载/上传均支持逗号分隔候选列表，运行时 `PickFastestAsync`/`PickFastestUploadAsync` 短测选优。下载默认腾讯/华为/阿里/npmmirror 四个国内镜像（`ubuntu/ls-lR.gz` 等大文件），实测 37 Mbps（原 Cloudflare 仅 6~14 Mbps）。
- 上传：默认 `mirrors.huaweicloud.com/`（POST 返回 200，真实接收）+ Cloudflare 兜底。华为云对突发 POST 会 429，故上传改为 1~2 并发 + 120ms 节流 + 连续失败 3 次才换端点；实测稳定 12~29 Mbps（Cloudflare 上传仅 3~7 Mbps，之前的低值其实是国际链路瓶颈）。
- 默认值：MQTT broker → broker-cn.emqx.io:1883（实测可连，CONNACK 547ms）；TCP 目标增加 www.taobao.com:443；STUN 列表 bilibili 在前，境外 3 台仅兜底。
- 报告新增：下载/上传测速源分别显示；上传经镜像站时标注"数值偏保守"。
- 验证：连续 3 次冒烟均走国内源无失败，总分 90+；发布版复验通过。
- 分发包：NetToolbox_v1.8_绿色版.zip（66.8MB / 464 文件），已删除 v1.6。
