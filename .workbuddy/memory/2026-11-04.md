## 网络测试工具箱 NetToolbox（WPF / .NET 8）
- 用户需求：Windows 网络稳定性评估工具（DNS / TCP / UDP / NAT），可设压测时长，输出 HTML 报告。
- 选型（用户确认）：WPF 桌面 GUI + C#/.NET 8 + 自包含 HTML 报告。
- 项目位置：`NetToolbox/`，构建命令：`C:/Users/ZJU/.dotnet/dotnet.exe build -c Release`（SDK 装在用户目录 `~/.dotnet`，winget 源损坏，用官方 dotnet-install.ps1 装的）。
- 架构：`Net/`（手写 DNS over UDP 探针 DnsProbe + 简化 STUN 客户端 StunClient）、`Testers/`（DNS/TCP/UDP/NAT 四个 ITester）、`Engine/TestEngine`（阶段一并行压测 + 阶段二 NAT 串行）、`Report/ReportGenerator`（内联 SVG 图表零依赖 HTML）、`ViewModels/MainViewModel`。
- 评分体系：DNS 25% + TCP 30% + UDP 20% + NAT 25%，按启用维度归一化；档位 ≥90 优秀 / ≥75 良好 / ≥60 一般 / 否则较差。
- NAT 类型判定：同一 socket 向两个不同 STUN 服务器比较映射地址（对称 vs 锥形）；容量测试：100/250/500/1000/2000 梯度并发 UDP 会话找成功率骤降点。
- 自检模式：`NetToolbox.exe --smoke [秒]` 端到端跑引擎并生成报告 + smoke.log。
- 验证结果：DNS 94 分、TCP 96 分（真实网络）；本沙箱屏蔽 UDP 3478 端口，STUN 维度显示"不可用"属环境限制，用户真机上正常。
- 注意：报告输出在 exe 同目录 `Reports/`；如需单文件发布：`dotnet publish -c Release -r win-x64 --self-contained -p:PublishSingleFile=true`。

## NAT 评估为 0 的问题排查与修复（v1.1）
- 原因：默认 STUN 服务器 stun.miwifi.com / stun.qq.com 已失效（本机实测无响应），非用户网络问题。
- 本机实测可用 STUN：stun.chat.bilibili.com:3478、stun.l.google.com:19302；不可用：miwifi/qq/hitv/cdnbye/cloudflare/syncthing。
- 修复：默认 STUN 列表改为 bilibili+google+备份；NatTester 类型探测与容量测试均改为逐个尝试候选 STUN 取可用项；单可用 STUN 时降级为"确认存在 NAT"。
- 修复后冒烟：NAT 检出 Full Cone、容量 250/250 全通、总分 94+。
- 单文件发布（PublishSingleFile）在本机被安全软件锁 exe（GenerateBundle MSB4018 IOException），改用自包含文件夹版打包。
- 分发包：`NetToolbox_v1.1_绿色版.zip`（66.8MB，解压后运行文件夹内 NetToolbox.exe）。

## v1.2：新增 MQTT 长连接稳定性维度（用户核心诉求）
- 用户场景：网关经该网络 MQTT 连平台频繁断线/无法登录，但旧版 TCP 短连接测试显示"不难看"——短连接测不出 NAT 空闲回收/心跳超时类断连。
- 新增 MqttStabilityTester：极简 MQTT 3.1.1 客户端（CONNECT/CONNACK/PINGREQ/PINGRESP/DISCONNECT，明文 1883），按 KeepAlive 周期心跳，统计断线次数/存活时长/重连耗时/CONNACK 返回码（区分网络问题 vs 认证拒绝 rc=4/5）。
- 配置新增：MqttBroker（默认 broker.emqx.io:1883，用户应改成自己平台地址）、MqttKeepAliveSeconds(60)、EnableMqtt。
- 权重：mqtt 0.30，总评分按启用维度归一化。
- UDP 维度报告新增"使用的 STUN 服务器"标注（google 判定为国际链路提示跨境延迟影响）。
- 冒烟验证：连公共 EMQX broker 成功，CONNACK 0x00，心跳 100%，0 断线，89 分。
- 分发包：NetToolbox_v1.2_绿色版.zip（66.8MB）。

## v1.3：域名解析兜底（家里网络 TCP/UDP/MQTT 全跳过问题）
- 原因：用户"以太网"网卡 DNS 被配置为 8.8.8.8+114（WLAN 正常 192.168.3.1）。国内直连 8.8.8.8:53 常超时（nslookup 实测），测试期间系统解析全失败 → 依赖 Dns.GetHostAddressesAsync 的 TCP/STUN/broker 解析全挂 → 三维度跳过；而 DNS 维度直连 223.5.5.5 不走系统解析所以正常。
- 修复：新增 Net/AddrResolver（系统解析失败 → 自动直连 223.5.5.5/119.29.29.29 查 A 记录兜底），DnsProbe 增加 QueryAAsync+响应 A 记录解析器；TCP/MQTT/STUN 解析全部改走 AddrResolver。
- 建议用户：把以太网 DNS 改回 223.5.5.5 或自动获取。
- 分发包：NetToolbox_v1.3_绿色版.zip（66.8MB）。
